Operations admission and provisioning recovery

Review how operations exclude each other, why provisioning needs a durable reservation, and what remains the operator’s responsibility after interruption.

Approval boundary: ownership and safe refusal/manual recovery direction are approved. The complete design and implementation plan are not. The admission mechanism is not implemented.
01 / Scope and ownership

Two locks and one durable reservation

Coordinate cooperating Taskman operations on one dedicated host while retaining controller-driven pyinfra and the existing lifecycle lock.

What each mechanism owns
MechanismLifetime and responsibilityBoundary / cost
/etc/taskman/admission.lockRoot-owned 0600 descriptor flock. Host-owned procedures hold it through consequential work and final evidence, including lifecycle unlock/wait intervals.Fixed host namespace prevents differing install-root settings from evading coordination. Supported boundary: one Taskman installation per Ubuntu 26.04 amd64 host. Unrelated administrator commands, OS maintenance, malicious interference and multi-installation hosting remain outside this coordination contract.

Current baseline: provisioning convergence precedes locked genesis; scheduled backups use the lifecycle lock. The admission mechanism shown here is proposed behavior.

Inherited contracts: deployment topology, artifact/backup/restore authority and existing confirmations stay with the deployment architecture and operations contracts.

02 / Provisioning sequence

Reserve before convergence; release after verified finish

The durable record bridges ordinary SSH commands. Holding a separate short-lived flock command would not protect later pyinfra writes.

Begin is an ordered boundary

  1. After confirmation, acquire admission then lifecycle, both nonblocking. A conflicting active legacy backup returns 12 before reservation or timer mutation.
  2. Revalidate confirmed authority; capture prior timer policy; atomically publish and sync the reservation.
  3. Disable/stop an existing timer. Release lifecycle while draining queued/running backup work; keep admission held.
  4. Reacquire lifecycle and validate suspended scheduler plus non-scheduler authority. Release both descriptors only after the validated begin receipt.

Finish proves a safe endpoint

  1. Every dispatched operational command has returned; genesis has verified durable successful history.
  2. Under admission then lifecycle, match the record, desired target, database/protected inputs and exact compatible backup-package checksum.
  3. Verify application readiness with the owned suspension exception; require known managed operational jobs quiescent.
  4. Restore timer policy synchronously; remove only the matching record and sync its parent. Release admission last.
Failure after publication: retain the reservation and backup suspension unless explicit finish succeeds. This includes known convergence failures. Lost begin replies require inspection/recovery; never replay begin automatically. Timer state must be observed if suspension itself failed.

03 / Failure and recovery

A retained reservation requires inspection

Loss of the caller does not guarantee termination of remote commands or service-manager work. A free flock, missing PID, old timestamp or retained owner ID proves neither completion nor quiescence.

Proposed operator commands and their limits
CommandRequired evidence / consentWhat it changes
inspect-admission ENVSSH host-key/privilege checks; no application-credential decryption required. Read-only even on a fresh host.Reports safe reservation projection and transient contention. Does not assert idle/running from a momentary free lock or take an unprotected lifecycle snapshot.
recover-provision ENV OWNER_IDExact valid record/configuration; admission then lifecycle; known jobs quiescent; verified completed selection/history, credentials/database and compatible scheduler. Real-terminal typed ENV OWNER_ID.Restore saved timer policy, then remove the matching record. A valid previous completed selection is allowed; no release selection, migrations or infrastructure repair.
recover-provision ENV OWNER_ID --keep-backups-suspendedSame identity/quiescence/confirmation boundary; safe protected authority; timer disabled/inactive or wholly absent. Application readiness may be partial or unknown.Clear only the reservation. Preserve releases, backups, migration protections and restore bindings. Report that automatic backups remain disabled and report former policy.
resume-backups ENVNo reservation; complete selected-release/history and credential/database authority, full verification with stopped-scheduler exception, compatible installed package; interactive confirmation + fresh revalidation.Enable/start the existing timer. Already safely enabled/active is a verified no-op. Does not install packages, edit schedules or repair readiness.
Manual recovery cost: the operator must inspect and finish/stop outstanding pyinfra commands and transient systemd jobs and coordinate OS maintenance. Automated checks cover known managed work; they cannot prove that every administrator subprocess has stopped. Recovery never automatically kills commands or cancels database sessions.

Recovery/resume support --dry-run and --json. Dry-run does not mutate or confirm. No --yes, generic force bypass or noninteractive recovery apply. Changed owner/material facts require a new plan and confirmation. Missing/mismatched/unsafe reservation refuses with 10; neither lock file is deleted.

04 / Command admission

Who is admitted, and when

Manual acquisition is nonblocking. Scheduled backups wait at most five seconds. An unrelated reservation denies ordinary cooperating operations before consequential writes.

Proposed conflict and observation rules
Entry pointAdmission scopeSpecial condition
provisionDurable reservation through convergence, genesis and finish.Existing reservation refuses begin, even for the same owner ID.
Deploy, rollback, restore, manual backup, cleanupDescriptor held for the whole host procedure and final evidence.Admission remains held while lifecycle is released for scheduler waits.
Scheduled backup / retentionDescriptor plus reservation check; retain inner lifecycle.Open validated existing lock O_RDONLY, without create/write. Missing file refuses 10; preserve ProtectSystem=strict.
Interactive create-adminPrivileged foreground wrapper holds admission throughout TTY service invocation.Preserve real terminal, protected environment file and unprivileged execution. Admission denial propagates 12.
Coherent host observation and dry-run host probesShort admission scope for each coherent snapshot.Refuse unrelated reservation. Multiple controller probes do not become one atomic snapshot; apply still revalidates.
Local build, config/secret validation, helpNo host admission.Local input failures keep their original precedence.
Fresh-host observation creates nothing: when admission is absent, open an existing safe lifecycle inode without creation, or preserve genuinely absent installation/lifecycle authority. Check admission namespace absence before and after the snapshot; appearance discards it and retries through ordinary admission. Missing lock with a present reservation is unsafe.

Evidence required before accepting implementation

The source records independent written-design review and historical sequential native provisioning. Those establish neither overlap safety nor acceptance of later implementation. The current application test baseline is recorded in the workstream handoff.

  • Local checks must cover contention, owner restrictions, nested calls, legacy-job draining, scheduler upgrade, retained failure evidence, reboot persistence, recovery guards, noncreating bootstrap and real-terminal behavior.
  • Verify the actual isolated helper packages and pinned release runtime; controller/source tests alone do not establish deployed-consumer behavior.
  • Separately authorized native acceptance must exercise real SSH/systemd overlap refusal, first/repeat provisioning, interrupted recovery, disabled policy, reboot suspension and compatible timer restoration.
